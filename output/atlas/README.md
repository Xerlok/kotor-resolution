# Map-note atlas — how to annotate it

90 PNGs, one per module that has map notes, covering all **340 notes** in the
game. Generated by `python tools/map_note_atlas.py build`, 16 MB total.
`atlas_index.csv` is the machine-readable half — do not edit or move it, the
ingest step reads every coordinate it needs from there.

## What you are looking at

| element | meaning |
|---|---|
| **yellow crosshair** | the note's authored (vanilla) position — this is its identity |
| **numbered yellow badge** | which note it is; the number matches the legend on the right |
| **thin white ring** | the game's real 14×14 px note icon, to scale — use it to judge "would this icon actually cover the thing it names" |
| **green cross + green line** | where our current patch already moves that note (175 of them). The atlas doubles as a review of those |
| **faint teal wash** | walkable floor. A note should never sit off it |
| **cyan corner squares** | registration marks. Leave them intact |

The map is drawn at **4× the game's map-pixel space** (440×256), so one map pixel
is a 4×4 block and a steady hand is about ±0.75 map px — finer than the engine's
own rounding. Only the left 440 px are shown because the engine never draws the
rest of the texture.

## What to draw

**One magenta line per note you want moved: from that note's marker to the exact
spot where it belongs, finishing with a small circle or blob at the destination.**

- Ink: **magenta `#FF00FF`**, brush 2–4 px. Pure red `#FF0000` also works as a
  fallback. Magenta is the safe choice because there is **not one magenta pixel
  in any of the game's 88 map textures**, whereas the art does contain saturated
  red (144 px in `m17ab` alone).
- The end **nearest a marker** identifies the note. The **far end** is the target.
  So identity comes from geometry, not handwriting — nothing has to be legible.
- **One line per note.** Try not to let two lines cross or touch: two strokes that
  touch merge into one shape and I have to flag them instead of reading them.
- A note you leave untouched stays exactly where it is. No mark = "this one is
  fine".
- **Crowded notes** (14 of the 340, flagged in the legend — `manm28aa`,
  `tar_m02ab`, `unk_m44aa` and a few others): two notes sit within a few map
  pixels, so their crosshairs cannot be told apart. For those, **start your line
  at the numbered badge**, which is always well clear of every other badge. Their
  badges are drawn further out for exactly this reason.
- Save as **PNG**, no resizing, no cropping, no JPEG. If a resize does happen, the
  four cyan registration squares let me undo it — but don't rely on that.

## What happens when you send them back

1. `ingest` finds the magenta strokes, resolves each to (note, target map pixel).
2. Each target is converted to a corrected world position with the *same*
   calibration used to draw the atlas, then snapped to a whole map pixel (the
   engine draws at `int(px + 0.5)`, so a fractional target lands on a rounding
   boundary).
3. Each becomes an `override` row in `output/note_decisions.csv` — the reviewed
   authority the existing pipeline already honours.
4. `note_corrections.py finalize` re-validates everything (round-trip exact, in
   the engine's draw bounds, position key unique across all 340 notes) and
   `note_table_patch.py` rebuilds the exe table.

You will get back, before anything is patched: how many strokes were read, which
note each was assigned to with the distance from the anchor, anything ambiguous,
and a before/after render of every correction to confirm.

## One thing to know before you start

The exe table currently holds 175 corrections in a 3,485-byte code cave at
16 bytes per entry, and **544 bytes are left — 34 more notes.** Correcting a
large share of the remaining 165 needs more room than the cave has. That is
solvable (a new PE section gives effectively unlimited space, and the match
routine only needs its two bounding addresses changed) but it is real work, so
annotate freely and let the table growth be my problem, not a reason to hold back.
